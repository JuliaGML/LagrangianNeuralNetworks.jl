Lagrangian Neural Network

A Lagrangian neural network learns a scalar Lagrangian $L(q, \dot{q})$ instead of the dynamics themselves. The dynamics are then whatever that Lagrangian implies, through the Euler–Lagrange equations

\[ \frac{d}{dt}\frac{\partial{}L}{\partial\dot{q}} = \frac{\partial{}L}{\partial{}q}.\]

This is the Lagrangian counterpart of the Hamiltonian neural network of HamiltonianNeuralNetworks.jl: there the network is a Hamiltonian and the dynamics come from a Poisson tensor, here the network is a Lagrangian and the dynamics come from a variational principle.

Each section below describes one method, cites its source, and documents its functions. The tutorial trains four models of the harmonic oscillator with them and compares the results.

The Architecture

LagrangianNeuralNetwork is the network of Cranmer et al. [1]: a fully connected network from the state $x = [q; \dot{q}]$ to a scalar, which is read as the Lagrangian. Its default activation is softplus, which the source chose from a search over activations because a network of ReLUs has a zero second derivative, and the dynamics need the second. Hamzaogullari and Ozakin [2] find GeLU the best activation on their pendulum benchmarks; the package does not offer it yet.

The network is unstructured: any scalar function of the state is a candidate. The structured architecture $L = \frac{1}{2}\dot{q}^TM(q)\dot{q} - V(q)$ of Lutter et al. [3], with the mass matrix $M = \hat{L}\hat{L}^T$ from a Cholesky factor of positive diagonal, excludes singular velocity Hessians by construction; the package does not offer it yet.

LagrangianNeuralNetworks.softplus — Function
softplus(x)

The activation $\log(1 + e^x)$, with the element type of x, evaluated in the split form $x + \log(1 + e^{-x})$ for $x > 0$ and $\log(1 + e^{x})$ otherwise. Neither branch overflows: the positive one adds a term that decays to 0, the negative one an exponent of at most 1. For a large positive x the value is x to the accuracy of x, and for a large negative one $e^x$ to the accuracy of exp. So softplus(-Inf) is 0, softplus(Inf) is Inf, and softplus(0) is log 2.

It is the default activation of LagrangianNeuralNetwork. With tanh, LNNLoss does not learn the harmonic oscillator: the solve against $\nabla_{\dot{q}}\nabla_{\dot{q}}L$ amplifies every sample where that block is near zero. With softplus it does; scripts/reproduction/k2_harmonic_oscillator.jl trains it on 16 seeds in each precision.

softplus is a symbolic primitive, so the compiled first and second derivatives of a network are the logistic $\sigma$ and its derivative $\sigma(1 - \sigma)$, both bounded and finite in Float32 and in Float64: the symbolic derivative of softplus is registered as the logistic, and the split is never differentiated symbolically, so its tie-break at 0 changes no derivative.

LogExpFunctions also exports a softplus; a module that loads both packages qualifies the name.

The Loss

Expanding the Euler–Lagrange equations along a trajectory gives

\[ \nabla_{\dot{q}}\nabla_{\dot{q}}L\,\ddot{q} + (\nabla_q\nabla_{\dot{q}}L)^T\dot{q} = \nabla_qL,\]

so the acceleration the learned Lagrangian predicts is

\[ \ddot{q} = (\nabla_{\dot{q}}\nabla_{\dot{q}}L)^{-1} \left( \nabla_qL - (\nabla_q\nabla_{\dot{q}}L)^T\dot{q} \right),\]

which is what LagrangianNeuralNetworks.lagrangian_acceleration computes and what LagrangianNeuralNetworks.LNNLoss compares against the data. This is the loss of Cranmer et al. [1].

The transpose is not cosmetic. $\nabla_q\nabla_{\dot{q}}L$ is indexed $[i, j] = \partial^2L/\partial{}q_i\partial\dot{q}_j$, while the chain rule contracts the first index with $\dot{q}$. It disappears only for a Lagrangian whose position–velocity coupling happens to be symmetric, which is why the test for this asserts a closed form whose coupling deliberately is not.

LagrangianNeuralNetworks.LNNLoss — Type
LNNLoss <: NetworkLoss

The loss for a Lagrangian neural network.

The network output is a scalar Lagrangian $L(q, \dot{q})$. The loss compares the acceleration its Euler–Lagrange equations predict against the acceleration in the data:

\[ \mathtt{loss}(\mathcal{NN}, \mathtt{input}, \mathtt{output}) = ||\ddot{q}(\mathtt{input}) - \mathtt{output}|| \,/\, ||\mathtt{output}||,\]

where $\mathtt{input}$ stacks $q$ on $\dot{q}$ and is therefore $2n$ rows tall, and $\mathtt{output}$ is $\ddot{q}$ and is $n$ rows tall. See lagrangian_acceleration for $\ddot{q}$.

LagrangianNeuralNetworks.lagrangian_acceleration — Function
lagrangian_acceleration(arch::LagrangianArchitecture)

Compute an executable expression of the acceleration that the Lagrangian arch predicts.

The Euler–Lagrange equations of a Lagrangian $L(q, \dot{q})$ are

\[ \frac{d}{dt}\frac{\partial{}L}{\partial\dot{q}} = \frac{\partial{}L}{\partial{}q},\]

which, expanded along a trajectory, reads

\[ \nabla_{\dot{q}}\nabla_{\dot{q}}L\,\ddot{q} + (\nabla_q\nabla_{\dot{q}}L)^T\dot{q} = \nabla_qL,\]

so the acceleration is

\[ \ddot{q} = (\nabla_{\dot{q}}\nabla_{\dot{q}}L)^{-1} \left( \nabla_qL - (\nabla_q\nabla_{\dot{q}}L)^T\dot{q} \right).\]

The transpose is not cosmetic. $\nabla_q\nabla_{\dot{q}}L$ is indexed $[i, j] = \partial^2L/\partial{}q_i\partial\dot{q}_j$, while the chain rule contracts the first index with $\dot{q}$. It disappears only for a Lagrangian whose position–velocity coupling happens to be symmetric.

Implementation

The gradient and the Hessian of the network with respect to its input come from LagrangianDerivatives, compiled once when lagrangian_acceleration is called. Trailing input dimensions beyond the first are flattened on the way in and restored on the way out, so an input of size $(2n, s, B)$, which is what Batch hands the loss, yields an acceleration of size $(n, s, B)$.

Why the Derivatives Are Symbolic

The loss needs the second derivative of the network with respect to its input, and then its own derivative with respect to the network parameters. Taking the inner one with Zygote inside the loss does not work: the parameter gradient then fails with MethodError: no method matching getindex(::IdDict{Any, Any}). The gradient and Hessian are therefore built as symbolic expressions with SymbolicNeuralNetworks and compiled, so that only one differentiation is left for Zygote to do. This is the same route that hamiltonian_vector_field of HamiltonianNeuralNetworks.jl takes, and for the same reason.

LagrangianNeuralNetworks.LagrangianDerivatives — Type
LagrangianDerivatives(arch::Architecture; hessian = true)

Compile the gradient and the Hessian of the network of arch with respect to its input, once.

arch is any architecture whose Chain has a scalar output and that has a method of AbstractNeuralNetworks.dim, the input dimension $2n$; it need not be a LagrangianArchitecture. Evaluate the result with input_gradient and input_hessian. With hessian = false, only the gradient is built and compiled, and input_hessian throws an ArgumentError.

Implementation

The gradient and the Hessian are built as symbolic expressions with SymbolicNeuralNetworks.Jacobian, applied once and then again to its own result, and compiled with build_nn_function. They are not taken with Zygote inside a loss: differentiating a loss that itself contains a Zygote.gradient with respect to the network parameters fails with MethodError: no method matching getindex(::IdDict{Any, Any}). This is the route hamiltonian_vector_field of HamiltonianNeuralNetworks.jl takes, and for the same reason.

The compiled functions flatten a batch along the columns, $(1, 2n\cdot{}B)$ for the gradient and $(2n, 2n\cdot{}B)$ for the Hessian, so input_gradient and input_hessian reshape their output.

The Euler–Lagrange Residual

EulerLagrangeLoss asks the learned Lagrangian to satisfy the Euler–Lagrange equations on the data, as the residual of the first equation above, with no solve against the velocity Hessian [4]. A velocity Hessian near zero then does not amplify a sample. The price is that the zero Lagrangian, and every null Lagrangian, has the loss zero: the loss is used together with a normalisation and a scale condition, as the next section describes.

LagrangianNeuralNetworks.EulerLagrangeLoss — Type
EulerLagrangeLoss <: NetworkLoss

The Euler–Lagrange residual loss for a Lagrangian neural network (Offen 2025, App. B).

The loss asks the learned Lagrangian to satisfy the Euler–Lagrange equations on the data, with no solve for the acceleration:

\[ \mathtt{loss}(\mathcal{NN}, \mathtt{input}, \mathtt{output}) = \frac{1}{B}\sum_{b=1}^B \left\| \nabla_{\dot{q}}\nabla_{\dot{q}}L\,\ddot{q}_b + (\nabla_q\nabla_{\dot{q}}L)^T\dot{q}_b - \nabla_qL \right\|^2,\]

with the derivatives of $L$ taken at sample $b$ and $(\nabla_q\nabla_{\dot{q}}L)_{ij} = \partial^2L/\partial{}q_i\partial\dot{q}_j$. input stacks $q$ on $\dot{q}$ and has $2n$ rows, and output is $\ddot{q}$ and has $n$; trailing dimensions are samples too, so an input of size $(2n, s, B)$ goes with an output of size $(n, s, B)$, and the mean runs over all $sB$ samples. See _euler_lagrange_residual for the residual of one sample.

Unlike LNNLoss, the loss inverts no Hessian, so a velocity Hessian near zero does not amplify a sample. It is not normalised: the zero Lagrangian has the loss zero on any data.

A size mismatch of input and output throws a DimensionMismatch, and an empty batch an ArgumentError. NaN and Inf in the data propagate to the value.

Normalisation

A Lagrangian is determined by its dynamics only up to a constant, a total time derivative and a factor (see the non-uniqueness of a Lagrangian). Offen [4] fixes the value and the momentum of the Lagrangian at one base point, Prop. 3.1, which removes the constant and the linear gauge and which NormalisedLagrangian does for every value of the parameters, and fixes the factor through the determinant of the velocity Hessian at that point, (B.1). ScaleCondition is that condition as a penalty, and DiscreteScaleCondition the condition (B.2) on the mixed Hessian of a discrete Lagrangian; Ober-Blöbaum and Offen [5] fix the scale of a discrete Lagrangian by a condition of this kind, (13)–(15).

LagrangianNeuralNetworks.NormalisedLagrangian — Type
NormalisedLagrangian(arch::LagrangianArchitecture; base = zeros(2n), value = 0, momentum = zeros(n))

The Lagrangian of arch with its value and its momentum fixed at one base point (Offen 2025, Prop. 3.1), where $2n$ is dim(arch):

\[ \tilde{L}(x) = L(x) - L(x_b) - (\dot{q} - \dot{q}_b)^T\left(\nabla_{\dot{q}}L(x_b) - p_b\right) + c_b,\]

with $x = (q, \dot{q})$, $L$ the network of arch, $x_b$ = base, $\dot{q}_b$ its last $n$ entries, $c_b$ = value and $p_b$ = momentum. Then $\tilde{L}(x_b) = c_b$ and $\nabla_{\dot{q}}\tilde{L}(x_b) = p_b$ for every value of the parameters, which removes the constant and the linear gauge of a Lagrangian. With value and momentum both zero, the scale is not fixed, and is left to a condition of its own.

The network takes the same input as that of arch and has the same parameters, nested under the key L1. Every loss of a continuous Lagrangian takes a NormalisedLagrangian as it takes arch.

$\nabla_{\dot{q}}L(x_b)$ is computed in the forward pass, by a reverse pass over the layers of Chain(arch), so it is part of the expression that SymbolicNeuralNetworks traces and it depends on the parameters. That reverse pass supports Dense and Linear layers with the activations tanh, softplus and identity.

base and momentum are copied at construction. base, value and momentum are converted to the element type of the parameters. Where the network of arch is not finite at the base point, the network of the wrapper is not finite anywhere.

A base or a momentum that is no AbstractVector throws a TypeError. A base of a length other than $2n$ or a momentum of a length other than $n$ throws a DimensionMismatch. An odd dim(arch), a layer of Chain(arch) that is no Dense, and an activation other than the three above throw an ArgumentError.

LagrangianNeuralNetworks.ScaleCondition — Type
ScaleCondition(arch; base = zeros(2n), value = 1)

The scale normalisation of a continuous Lagrangian (Offen 2025, (B.1)):

\[ \left( \det\nabla_{\dot{q}}\nabla_{\dot{q}}L(x_b) - c \right)^2\]

at the point $x_b =$ base $= [q_b; \dot{q}_b]$, with $c =$ value. It fixes the factor by which a Lagrangian is determined. arch is a LagrangianArchitecture of $2n$ inputs.

The result r is called as r(ps, input); the value does not depend on input, whose row count must still be $2n$. base and value are converted to the element type of input, which the value has. A value that is not positive and finite throws an ArgumentError, and a base of another length than $2n$ or an input of another row count a DimensionMismatch.

source
LagrangianNeuralNetworks.DiscreteScaleCondition — Type
DiscreteScaleCondition(arch, Δt; base = zeros(2n), value = 1)

The scale normalisation of the midpoint discrete Lagrangian of a continuous Lagrangian (Offen 2025, (B.2)):

\[ \left( \det\Lambda(x_b) - c \right)^2, \qquad \Lambda = -\Delta{}t\,\frac{\partial^2L_d}{\partial{}q_0\partial{}q_1},\]

with $x_b =$ base the pair $[q_0; q_1]$, $\Lambda$ at its midpoint (see _mixed_hessian), and $c =$ value. The source has $\det\partial^2L_d/\partial{}q_0\partial{}q_1$; the package uses $\det\Lambda = (-\Delta{}t)^n\det\partial^2L_d/\partial{}q_0\partial{}q_1$, which tends to the continuous $\det\nabla_{\dot{q}}\nabla_{\dot{q}}L$ of ScaleCondition as $\Delta{}t \to 0$.

The result r is called as r(ps, input), as that of ScaleCondition is, with the same conversions and refusals; a timestep that is not positive and finite throws an ArgumentError.

Regularity

A Lagrangian whose velocity Hessian is singular does not determine an acceleration, and a discrete Lagrangian whose mixed Hessian is singular does not determine the next position. Offen and Ober-Blöbaum [6] penalise the norm of the inverse of that Hessian, and Offen and Ober-Blöbaum [7] tame the penalty so that it vanishes wherever the inverse is small enough, (34); Lishkova et al. [8] penalise a small determinant through a sigmoid. VelocityHessianRegulariser is the penalty of a continuous Lagrangian, and MixedHessianRegulariser that of the midpoint discrete Lagrangian, in the three forms. RegularisedLoss adds weighted penalties, these or the scale conditions, to any loss of the package.

LagrangianNeuralNetworks.RegularisedLoss — Type
RegularisedLoss(loss, terms...)

The loss loss, a NetworkLoss, plus weighted penalties: each term is a pair weight => r, and the value is

\[ \mathtt{loss}(ps, \mathtt{input}, \mathtt{output}) + \sum_k w_k\,r_k(ps, \mathtt{input}).\]

A penalty r is any callable r(ps, input), such as VelocityHessianRegulariser, MixedHessianRegulariser, ScaleCondition or DiscreteScaleCondition. Each weight is converted to the element type of input; with no terms, the value is that of loss. A weight that is negative, NaN or Inf throws an ArgumentError. A weight of 0 is allowed, and its penalty is not evaluated, so a penalty of Inf or NaN adds nothing there. RegularisedLoss checks no row count itself: it evaluates loss before its penalties, so data that loss refuses throw the error of loss.

LagrangianNeuralNetworks.VelocityHessianRegulariser — Type
VelocityHessianRegulariser(arch)

The regularity penalty of a continuous Lagrangian, the continuous counterpart of the penalty (11) of Offen & Ober-Blöbaum 2023 (see MixedHessianRegulariser, whose $\Lambda$ tends to the velocity Hessian as $\Delta{}t \to 0$): the mean over the samples of

\[ \left\| (\nabla_{\dot{q}}\nabla_{\dot{q}}L)^{-1} \right\|_F^2 ,\]

which grows where the velocity Hessian is near singular, as it is for a null or a degenerate Lagrangian. arch is a LagrangianArchitecture.

Against the continuous penalty $\sum\|(\partial^2L/\partial\dot{q}^2)^{-1}\|$, the norm is here squared, taken in the Frobenius norm in place of the spectral norm (the two are equal for $n = 1$, and the Frobenius norm is an upper bound otherwise), and averaged over the samples.

The result r is called as r(ps, input), with input the points $[q; \dot{q}]$: $2n$ rows, and any trailing dimensions, which count as samples. The value has the element type of input. A singular velocity Hessian gives Inf, and an input of another row count than $2n$ throws a DimensionMismatch. Add it to a loss with RegularisedLoss.

source
LagrangianNeuralNetworks.MixedHessianRegulariser — Type
MixedHessianRegulariser(arch, Δt; form = :tamed)

The regularity penalty of the midpoint discrete Lagrangian $L_d(q_0, q_1) = \Delta{}t\,L((q_0 + q_1)/2, (q_1 - q_0)/\Delta{}t)$ of a continuous Lagrangian: the mean over the pairs $[q_0; q_1]$ of a penalty of

\[ \Lambda = -\Delta{}t\,\frac{\partial^2L_d}{\partial{}q_0\partial{}q_1},\]

see _mixed_hessian. $\Lambda$ tends to the velocity Hessian $\nabla_{\dot{q}}\nabla_{\dot{q}}L$ as $\Delta{}t \to 0$, so a threshold on it means the same as one on the velocity Hessian. arch is a LagrangianArchitecture, and Δt the timestep.

The three forms:

  • :inverse: $\|\Lambda^{-1}\|_F^2$ (Offen & Ober-Blöbaum 2023, (11)). The source, a paper on PDEs, penalises $\|(D_1D_2L_d)^{-1}\|^2$ in the spectral norm; with $\Lambda = -\Delta{}t\,D_1D_2L_d$, this is that penalty divided by $\Delta{}t^2$, and in the Frobenius norm.
  • :tamed: $\mathrm{relu}(1 - 10/\|\Lambda^{-1}\|_F^2)$ (Offen & Ober-Blöbaum 2024, (34)), which is 0 wherever $\|\Lambda^{-1}\|_F^2 \le 10$; the threshold 10 applies to the Frobenius norm of $\Lambda^{-1}$.
  • :sigmoid: $1 - \sigma(0.01\det(\Lambda)^2)$ with $\sigma(x) = 1/(1 + e^{-x})$ (Lishkova 2023, the degeneracy term added to the cost function (14), with $m = 2$). The source uses $d = \det D_2D_1L_d$; here $\det\Lambda = (-\Delta{}t)^n\det D_1D_2L_d$, so that the three forms read the same matrix, and the square removes the sign.

A singular $\Lambda$ gives Inf for :inverse, 1 for :tamed and 1/2 for :sigmoid.

The result r is called as r(ps, input), with input the pairs $[q_0; q_1]$: $2n$ rows, and any trailing dimensions, which count as samples. The value has the element type of input, and Δt is converted to it. A timestep that is not positive and finite and an unknown form throw an ArgumentError, and an input of another row count than $2n$ a DimensionMismatch.

source
LagrangianNeuralNetworks._mixed_hessian — Function
_mixed_hessian(H, Δt)

The matrix $\Lambda = -\Delta{}t\,D_1D_2L_d$ of the midpoint discrete Lagrangian $L_d(a, b) = \Delta{}t\,L((a + b)/2, (b - a)/\Delta{}t)$, from the $2n\times{}2n$ Hessian H of $L$ at the midpoint, with $D_1D_2L_d[i, j] = \partial^2L_d/\partial{}a_i\partial{}b_j$.

By the chain rule, with H in the blocks $H_{qq}$, $H_{q\dot{q}}$ and $H_{\dot{q}\dot{q}}$, $H_{q\dot{q}}[i, j] = \partial^2L/\partial{}q_i\partial\dot{q}_j$,

\[ \Lambda = H_{\dot{q}\dot{q}} - \frac{\Delta{}t}{2}\left(H_{q\dot{q}} - H_{q\dot{q}}^T\right) - \frac{\Delta{}t^2}{4}H_{qq},\]

which tends to the velocity Hessian $H_{\dot{q}\dot{q}}$ as $\Delta{}t \to 0$. Δt is converted to the element type of H.

Training on Positions Alone

LagrangianNeuralNetworks.LNNLoss needs $\ddot{q}$ in the data. When only positions are available, LagrangianNeuralNetworks.VariationalMidpointLoss trains the same architecture through the discrete Euler–Lagrange equations of the midpoint discrete Lagrangian

\[ L_d(q_n, q_{n+1}) = \Delta{}t\, L\!\left( \frac{q_n + q_{n+1}}{2}, \frac{q_{n+1} - q_n}{\Delta{}t} \right),\]

which ask that $D_2L_d(q_n, q_{n+1}) + D_1L_d(q_{n+1}, q_{n+2}) = 0$ along the data. The loss is the mean squared residual of these equations, (16) of Ober-Blöbaum and Offen [5]. The residual needs only the first derivative of the network, because the chain rule through the midpoint is written out rather than taken with a nested Zygote.gradient; its default regulariser, LagrangianNeuralNetworks.MixedHessianRegulariser, needs the second.

LagrangianNeuralNetworks.VariationalMidpointLoss — Type
VariationalMidpointLoss <: NetworkLoss

The loss that trains a Lagrangian neural network on positions alone, through the discrete Euler–Lagrange equations of the midpoint discrete Lagrangian.

It needs three consecutive positions and the timestep between them — no velocities and no accelerations.

The midpoint discrete Lagrangian is

\[ L_d(q_n, q_{n+1}) = \Delta{}t\, L\!\left( \frac{q_n + q_{n+1}}{2}, \frac{q_{n+1} - q_n}{\Delta{}t} \right),\]

and the discrete Euler–Lagrange equations ask that

\[ D_2L_d(q_n, q_{n+1}) + D_1L_d(q_{n+1}, q_{n+2}) = 0 .\]

The loss is the mean over the samples of the squared residual (Ober-Blöbaum & Offen 2023, (16)), plus a weighted regularity penalty:

\[ \frac{1}{B}\sum_{b=1}^B \left\| D_2L_d(q_n, q_{n+1}) + D_1L_d(q_{n+1}, q_{n+2}) \right\|^2 + w\,r(ps, [q_n; q_{n+1}]).\]

The residual alone does not exclude a null Lagrangian: a constant, or $g(q)\cdot\dot{q}$ with $g = \nabla\varphi$ and $\varphi$ quadratic, has a discrete residual of zero on any data. The default penalty, MixedHessianRegulariser in the form :tamed, is 1 where the discrete Lagrangian is degenerate, as it is for those. The relative normalisation of the source is not applied.

Implementation

The two slot derivatives are written out with the chain rule rather than taken with a nested Zygote.gradient:

\[ D_1L_d = \frac{\Delta{}t}{2}\nabla_qL - \nabla_{\dot{q}}L, \qquad D_2L_d = \frac{\Delta{}t}{2}\nabla_qL + \nabla_{\dot{q}}L,\]

both evaluated at the midpoint. The residual needs only the first derivative of the network with respect to its input, and that comes from the compiled symbolic expression of LagrangianDerivatives, exactly as that of hamiltonian_vector_field of HamiltonianNeuralNetworks.jl does; the regulariser compiles its own derivatives. Written the other way — a Zygote.gradient inside the loss — the parameter gradient fails with MethodError: no method matching getindex(::IdDict{Any, Any}).

The Discrete Lagrangian Network

Lishkova et al. [8] learn the discrete Lagrangian $L_d(q_0, q_1)$ itself, as a network of two consecutive positions, (14), with the squared discrete Euler–Lagrange residual as the loss. DiscreteLagrangianNetwork is that network and DiscreteEulerLagrangeLoss that loss. The continuous Lagrangian a discrete one stands for is its inverse modified Lagrangian, (4) of the source, which inverse_modified_lagrangian reads off the network.

LagrangianNeuralNetworks.DiscreteLagrangianArchitecture — Type
DiscreteLagrangianArchitecture <: Architecture

The supertype of an architecture whose network is a discrete Lagrangian $L_d(q_0, q_1)$, a scalar function of two consecutive positions (Lishkova 2023, (14)).

It is no LagrangianArchitecture: its input [q_0; q_1] stacks two positions, not a position and a velocity, so a loss that reads a position and a velocity, such as LNNLoss, would take the second position for a velocity. A subtype needs two methods, AbstractNeuralNetworks.dim(arch), the input dimension $2n$, and Chain(arch), a chain of $2n$ inputs with a scalar output. The subtype of the package is DiscreteLagrangianNetwork, which DiscreteEulerLagrangeLoss trains and from which inverse_modified_lagrangian reads a continuous Lagrangian.

LagrangianNeuralNetworks.DiscreteLagrangianNetwork — Type
DiscreteLagrangianNetwork(n; width = 2n, nhidden = 1, activation = softplus)

The discrete Lagrangian $L_d(q_0, q_1)$ of Lishkova 2023, (14), as a network: a Dense layer of width neurons, nhidden more of them, and a bias-free Linear output layer. Its input [q_0; q_1] stacks two positions of $n$ entries, and its output is a scalar.

The network is a DiscreteLagrangianArchitecture, not a LagrangianArchitecture. DiscreteEulerLagrangeLoss trains it on positions alone, through the discrete Euler–Lagrange equations, and inverse_modified_lagrangian reads a continuous Lagrangian off it. The layers are those of LagrangianNeuralNetwork, with $2n$ inputs in place of dimin, and the default activation is softplus.

n, width and nhidden are stored as Int. n < 1, width < 1 and nhidden < 0 throw an ArgumentError.

LagrangianNeuralNetworks.DiscreteEulerLagrangeLoss — Type
DiscreteEulerLagrangeLoss(arch, Δt;
    regulariser = MixedHessianRegulariser(arch, Δt; form = :tamed), weight = 1)

The loss that trains a DiscreteLagrangianNetwork on positions alone, through the discrete Euler–Lagrange equations of the network itself:

\[ D_2L_d(q_{k-1}, q_k) + D_1L_d(q_k, q_{k+1}) = 0 .\]

It is the mean over the samples of the squared residual (Lishkova 2023, (14)), plus a weighted regularity penalty:

\[ \frac{1}{B}\sum_{b=1}^B \left\| D_2L_d(q_{k-1}, q_k) + D_1L_d(q_k, q_{k+1}) \right\|^2 + w\,r(ps, [q_{k-1}; q_k]),\]

with $D_1L_d$ and $D_2L_d$ the first and the last $n$ entries of the input gradient of the network, and $w$ = weight. The residual alone does not exclude a null discrete Lagrangian: a constant, and $g(q_0) - g(q_1)$ with $g$ linear, have a residual of zero on any data. The default penalty, MixedHessianRegulariser in the form :tamed, is 1 where the discrete Lagrangian is degenerate, as it is for those; its $\Lambda = -\Delta{}t\,D_1D_2L_d$ tends to the velocity Hessian of the continuous Lagrangian as $\Delta{}t \to 0$.

The residual needs only the first derivative of the network with respect to its input, which comes from the compiled symbolic expression of LagrangianDerivatives, and the regulariser compiles its own Hessian.

Constructor

arch is a DiscreteLagrangianArchitecture, Δt its timestep, regulariser a callable r(ps, input) and weight its weight $w$. The timestep is held by the regulariser, which the constructor builds from it; the loss itself refuses a timestep that is not positive and finite, and a weight that is negative, NaN or Inf, with an ArgumentError. With weight = 0 the regulariser is not evaluated, and the loss is the mean squared residual alone.

LagrangianNeuralNetworks.inverse_modified_lagrangian — Function
inverse_modified_lagrangian(nn::NeuralNetwork, Δt)
inverse_modified_lagrangian(Ld::Function, Δt)

The continuous Lagrangian that a discrete Lagrangian stands for, the inverse modified Lagrangian of Lishkova 2023, (4):

\[ L(q, \dot{q}) = \frac{1}{\Delta{}t}\, L_d\!\left(q - \frac{\Delta{}t}{2}\dot{q}, q + \frac{\Delta{}t}{2}\dot{q}\right),\]

the formula of the source divided by $\Delta{}t$. The division is deliberate: it makes the result approximate $L$ itself, and for the midpoint discrete Lagrangian $L_d$ of a continuous $L$ it is that $L$ exactly.

nn is a NeuralNetwork of a DiscreteLagrangianNetwork; with a function in its place, Ld(q_0, q_1) is called directly, which is how the identity above is checked against an analytic discrete Lagrangian.

The result f is called as f(q, q̇) on a pair of vectors q and q̇ or on a pair of n × B matrices, and on no other shape: a scalar for the vectors and a 1 × B array for the matrices, in the element type of q, which $\Delta{}t$ is converted to. A plain Ld is called on one pair of positions at a time, as two AbstractVectors — the columns of the pair on a matrix call — and must return a number or a one-element array. A q̇ of another size than q throws a DimensionMismatch, and so does a q of another row count than $n$ with the network method; a timestep that is not positive and finite throws an ArgumentError.

The Variational Integrator

A learned Lagrangian is rolled out by the variational integrator of its discrete Lagrangian: each step solves the discrete Euler–Lagrange equations for the next position by Newton's method [6]. DiscreteLagrangian is the discrete model, the midpoint rule of a continuous network or a discrete network itself, and variational_rollout the rollout.

LagrangianNeuralNetworks.DiscreteLagrangian — Type
DiscreteLagrangian(nn, Δt)
DiscreteLagrangian(nn)
DiscreteLagrangian(D₁L_d, D₂L_d, D₁D₂L_d)

The discrete Lagrangian $L_d(a, b)$ of two consecutive positions, the model that variational_rollout integrates, in its three forms.

DiscreteLagrangian(nn, Δt) is the midpoint discrete Lagrangian of a NeuralNetwork of a LagrangianArchitecture,

\[ L_d(a, b) = \Delta{}t\,L\!\left(\frac{a + b}{2}, \frac{b - a}{\Delta{}t}\right),\]

read through the chain rule as the two slot derivatives and the mixed Hessian

\[ D_1L_d = \frac{\Delta{}t}{2}\nabla_qL - \nabla_{\dot{q}}L, \qquad D_2L_d = \frac{\Delta{}t}{2}\nabla_qL + \nabla_{\dot{q}}L, \qquad D_1D_2L_d = \frac{\Delta{}t}{4}H_{qq} + \frac{1}{2}\left(H_{q\dot{q}} - H_{\dot{q}q}\right) - \frac{1}{\Delta{}t}H_{\dot{q}\dot{q}} = -\frac{\Lambda}{\Delta{}t},\]

all at the midpoint, with $\Lambda$ the $-\Delta{}t\,D_1D_2L_d$ that MixedHessianRegulariser builds from the same input Hessian. The timestep is converted to the element type of the network's parameters.

DiscreteLagrangian(nn) is a NeuralNetwork of a DiscreteLagrangianArchitecture, which is a discrete Lagrangian already: its input [a; b] gives $D_1L_d = g[1:n]$, $D_2L_d = g[n+1:2n]$ and $D_1D_2L_d = H[1:n, n+1:2n]$ as blocks of its own input gradient g and input Hessian H.

DiscreteLagrangian(D₁L_d, D₂L_d, D₁D₂L_d) takes three functions of (a, b) — the two slot derivatives as vectors of $n$ entries and the mixed Hessian as an $n\times{}n$ matrix, indexed $[i, j] = \partial^2L_d/\partial{}a_i\partial{}b_j$. It names no precision and no dimension of its own: a rollout takes both from the positions.

The slot derivatives and the momentum map $p = -D_1L_d$ are those of Offen 2023, Prop. 1, and Ober-Blöbaum & Offen 2023, §2.3. A timestep that is not positive and finite in the parameters' element type throws an ArgumentError, and so does a bare continuous network, whose message names DiscreteLagrangian(nn, Δt).

LagrangianNeuralNetworks.variational_rollout — Function
variational_rollout(model, q₀, q₁, N; momentum = false, tol, maxiter = 20)
variational_rollout(model, q₀, p₀, N; momentum = true, tol, maxiter = 20)

Roll a trajectory out of a discrete Lagrangian model: the n × (N + 1) matrix [q₀ q₁ … q_N] of the positions q₀ and q₁ and the N − 1 that follow them.

Each step solves the discrete Euler–Lagrange equations (Offen 2023, Prop. 1)

\[ D_2L_d(q_{k-1}, q_k) + D_1L_d(q_k, q_{k+1}) = 0\]

for $q_{k+1}$ by Newton's method, with $D_1D_2L_d(q_k, \cdot)$ as the Jacobian and $2q_k - q_{k-1}$ as the guess, until the 2-norm of the residual is at most tol. The positions are numbered from zero, so the message of a failed solve names the position it was solving for as q_k with that index.

With momentum = true the second argument is the momentum $p_0 = -D_1L_d(q_0, q_1)$ rather than a position: q₁ is recovered first, by solving $-D_1L_d(q_0, q_1) = p_0$ from the guess q₀, and the rollout then proceeds from the pair. Both forms take four positional arguments of the same types, which is why the keyword selects this one. N = 0 returns q₀ alone, as one column, and solves nothing.

tol defaults to $\sqrt{\epsilon(T)}$, absolute and in the units of the residual, which scale with the Lagrangian. maxiter counts Newton steps, and the residual is tested before the first step and after each one; a residual that is not finite stops the solve at once, and one that does not reach tol in maxiter steps throws an ErrorException naming the position.

The element type T of the result is the parameters' for a network model and float(promote_type(eltype(q₀), eltype(q₁))) for a model of functions, and the positions are converted to it, as is the momentum with momentum = true. model is a DiscreteLagrangian or a NeuralNetwork of a DiscreteLagrangianArchitecture; a continuous network throws an ArgumentError naming DiscreteLagrangian(nn, Δt).

N < 0, a tol that is not positive and a maxiter below one throw an ArgumentError; positions of another length than each other or than the network's throw a DimensionMismatch; a singular Jacobian throws a LinearAlgebra.SingularException.

Backward Error Analysis

A model trained on positions learns the Lagrangian whose midpoint rule reproduces the data, its inverse modified Lagrangian, which differs from the true Lagrangian of the data at $O(\Delta{}t^2)$. Ober-Blöbaum and Offen [5] give the map from the one to the other to second order in the timestep, (11), and Lishkova et al. [8] the inverse modified Lagrangian of a discrete network, (4). modified_lagrangian applies the map, and removes that offset.

LagrangianNeuralNetworks.modified_lagrangian — Function
modified_lagrangian(model, Δt)

The continuous Lagrangian whose exact flow the discrete model of model reproduces to $O(\Delta{}t^4)$, as the function (q, q̇) ↦ L + (Δt²/24)·[(L_q − L_qq̇·q̇)²/L_q̇q̇ − L_qq·q̇²] of two vectors of one entry.

This is the second-order backward error analysis of Ober-Blöbaum & Offen 2023, (11), in the direction that recovers the true Lagrangian. The midpoint rule reproduces the exact flow of its inverse modified Lagrangian, which for a continuous network is the network itself and for a DiscreteLagrangianNetwork is $L_{im}(q, \dot{q}) = L_d(q - \Delta{}t\dot{q}/2, q + \Delta{}t\dot{q}/2)/\Delta{}t$ (Lishkova 2023, (4)). The formula maps that inverse modified Lagrangian to the true one; its plus sign gives a frequency error of $O(\Delta{}t^4)$ on the harmonic oscillator and the opposite sign $O(\Delta{}t^2)$.

For a continuous network the derivatives are the compiled input derivatives of the network. For a DiscreteLagrangianArchitecture they are the chain rule through the midpoint, with H the blocks of the network's own input Hessian at [q − Δt q̇/2; q + Δt q̇/2]:

\[ L_q = \frac{D_1L_d + D_2L_d}{\Delta{}t}, \qquad L_{\dot{q}} = \frac{D_2L_d - D_1L_d}{2}, \qquad L_{qq} = \frac{H_{11} + H_{12} + H_{21} + H_{22}}{\Delta{}t},\]

\[ L_{q\dot{q}} = \frac{H_{12} + H_{22} - H_{11} - H_{21}}{2}, \qquad L_{\dot{q}\dot{q}} = \frac{\Delta{}t}{4}\left(H_{11} - H_{12} - H_{21} + H_{22}\right).\]

The analysis is one-dimensional: a model of more than one degree of freedom throws an ArgumentError, and so does a timestep that is not positive and finite in the element type of the parameters. A q or a q̇ of another length throws a DimensionMismatch. A zero $L_{\dot{q}\dot{q}}$ gives the IEEE value of the quotient, and no exception. The value has the element type of the network's parameters.

The Non-Uniqueness of a Lagrangian

The data fix the equations of motion, not the Lagrangian. If $L$ gives the dynamics, so does

\[ \tilde{L} = \rho\,L + c + \frac{d}{dt}F(q)\]

for every scale factor $\rho \neq 0$, every constant $c$ and every total time derivative of a function $F$ of the positions, and in one dimension even Lagrangians that are not of this form, inequivalent ones, give the same equations of motion. A learned Lagrangian is therefore not compared with the true one: a fit of the one to the other can be poor where the dynamics are learned well. The normalisation of Offen [4] removes the constant, the linear gauge and the scale, but a model without it is one representative of a whole class.

The package measures a learned model by what does not depend on the representative:

  • acceleration_error, the relative error of the acceleration that the model predicts on a grid of states, §7.3 of [4];
  • the energy $E = \dot{q}^T\partial_{\dot{q}}L - L$, which becomes $\rho E - c$ under the gauge, so that its level sets do not change, and energy_alignment, the mean $|\sin\theta|$ between the gradients of the learned and the true energy, the measure $\nu$ of §3.1 of [5];
  • trajectory_error, the largest distance between a rollout of the model and a reference trajectory.

LagrangianNeuralNetworks.energy — Function
energy(model)

The energy of the continuous Lagrangian of model, a callable E(q, q̇) = q̇ᵀ∂_q̇L − L of two vectors of $n$ entries, with the element type of the network's parameters.

It is the quantity a trajectory conserves when the Lagrangian does not depend on time, and it is the measure of a learned model whose level sets are compared with those of a reference (Offen 2025, §7.3). A Lagrangian is unique only up to a scale, a constant and a total time derivative, and the energy changes with exactly the first two: under $L \mapsto \rho L + c + \frac{d}{dt}F(q)$ it becomes $\rho E - c$. Its value therefore carries the gauge, and its gradient carries only the factor $\rho$, so its level sets are unchanged.

The field gradient of the result is the gradient of the energy with respect to the state $x = [q; \dot{q}]$,

\[ \nabla E = H\begin{pmatrix}0\\ \dot{q}\end{pmatrix} - \begin{pmatrix}\nabla_qL\\ 0\end{pmatrix},\]

from the compiled input gradient $\nabla_qL$ and the input Hessian $H$ of the network, which is what energy_alignment compares. It takes a vector of $2n$ entries.

energy needs a continuous Lagrangian, and a DiscreteLagrangianArchitecture throws an ArgumentError. A q or a q̇ of another length throws a DimensionMismatch.

LagrangianNeuralNetworks.acceleration_error — Function
acceleration_error(model, x, q̈_ref)

The relative acceleration error $\|\ddot{q}_{NN} - \ddot{q}_{ref}\| / \|\ddot{q}_{ref}\|$ of a learned Lagrangian, over the columns of x and of q̈_ref (Offen 2025, §7.3).

x is the state $[q; \dot{q}]$ of each sample, a $2n\times{}B$ matrix, and q̈_ref the reference acceleration, an $n\times{}B$ matrix. $\ddot{q}_{NN}$ is the acceleration the Euler– Lagrange equations of the network predict, $(\nabla_{\dot{q}}\nabla_{\dot{q}}L)^{-1}(\nabla_qL - (\nabla_q\nabla_{\dot{q}}L)^T\dot{q})$, which is lagrangian_acceleration; both norms are those of the whole $n\times{}B$ array.

The relative error is invariant under the gauge $L \mapsto \rho L + c + \frac{d}{dt}F(q)$ of the learned Lagrangian, because the acceleration is: $\rho$ cancels between the inverse velocity Hessian and the gradients, and $c$ and the total derivative drop out of them. Scaling the reference changes the error. model is a NeuralNetwork of a LagrangianArchitecture, and one of a DiscreteLagrangianArchitecture throws an ArgumentError. x of the wrong row count, and an acceleration of the wrong row or column count, throw a DimensionMismatch; no columns, and a q̈_ref whose norm is zero, throw an ArgumentError; and a singular $\nabla_{\dot{q}}\nabla_{\dot{q}}L$ throws a LinearAlgebra.SingularException.

LagrangianNeuralNetworks.energy_alignment — Function
energy_alignment(E, E_ref, points)

The mean over the columns x of points of $|\sin\theta|$, the angle between $\nabla E(x)$ and $\nabla E_{ref}(x)$. It is 0 where the two energies single out the same level sets at that point, whose gradients are then parallel, and 1 where those gradients are perpendicular.

This is the measure $\nu$ of Ober-Blöbaum & Offen 2023, §3.1, the mean of $|\det(\nabla E_{ref}/\|\nabla E_{ref}\|, \nabla E/\|\nabla E\|)|$, which their two-dimensional benchmarks use and which generalises to a state of $2n > 2$ entries as the sine of the angle. It is invariant under the gauge $L \mapsto \rho L + c + \frac{d}{dt}F(q)$, which multiplies $\nabla E$ by the same factor $\rho$ at every point, so $|\sin\theta|$ is unchanged.

points is a $2n\times{}B$ matrix of states. Each of E and E_ref is the result of energy, whose gradient is used, or a function x ↦ ∇E(x) of a state that returns the gradient of length $2n$: the energy of a benchmark has a closed-form gradient, and no dependency of this package differentiates an arbitrary function.

A point whose gradient is exactly zero for either energy has no direction, and is left out of the mean; when every point is, and when points has no column, an ArgumentError is thrown. The value has the element type of the gradients.

LagrangianNeuralNetworks.trajectory_error — Function
trajectory_error(Q, Q_ref)

The largest $\|\cdot\|_2$ distance between the columns of two trajectories, Q and Q_ref, each an $n\times{}k$ matrix whose column $k$ is the position at step $k$.

It is the error of a rollout against a reference solution — the measure of a learned model that a variational integrator needs, since a trajectory is what the model predicts and a position is what it is compared at (Offen 2025, §7.3). The worst column is taken rather than a mean, because a rollout that is right everywhere but one step is a rollout that has lost the trajectory.

Trajectories of different sizes throw a DimensionMismatch and empty ones an ArgumentError; a NaN in either gives NaN. The value has the element type of the positions.
