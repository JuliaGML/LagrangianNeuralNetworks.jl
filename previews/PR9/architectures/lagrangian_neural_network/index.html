Lagrangian Neural Network

A Lagrangian neural network learns a scalar Lagrangian $L(q, \dot{q})$ instead of the dynamics themselves. The dynamics are then whatever that Lagrangian implies, through the Euler–Lagrange equations

\[ \frac{d}{dt}\frac{\partial{}L}{\partial\dot{q}} = \frac{\partial{}L}{\partial{}q}.\]

This is the Lagrangian counterpart of the Hamiltonian neural network of HamiltonianNeuralNetworks.jl: there the network is a Hamiltonian and the dynamics come from a Poisson tensor, here the network is a Lagrangian and the dynamics come from a variational principle.

The loss

Expanding the Euler–Lagrange equations along a trajectory gives

\[ \nabla_{\dot{q}}\nabla_{\dot{q}}L\,\ddot{q} + (\nabla_q\nabla_{\dot{q}}L)^T\dot{q} = \nabla_qL,\]

so the acceleration the learned Lagrangian predicts is

\[ \ddot{q} = (\nabla_{\dot{q}}\nabla_{\dot{q}}L)^{-1} \left( \nabla_qL - (\nabla_q\nabla_{\dot{q}}L)^T\dot{q} \right),\]

which is what LagrangianNeuralNetworks.lagrangian_acceleration computes and what LagrangianNeuralNetworks.LNNLoss compares against the data.

The transpose is not cosmetic. $\nabla_q\nabla_{\dot{q}}L$ is indexed $[i, j] = \partial^2L/\partial{}q_i\partial\dot{q}_j$, while the chain rule contracts the first index with $\dot{q}$. It disappears only for a Lagrangian whose position–velocity coupling happens to be symmetric, which is why the test for this asserts a closed form whose coupling deliberately is not.

Why the derivatives are symbolic

The loss needs the second derivative of the network with respect to its input, and then its own derivative with respect to the network parameters. Taking the inner one with Zygote inside the loss does not work: the parameter gradient then fails with MethodError: no method matching getindex(::IdDict{Any, Any}). The gradient and Hessian are therefore built as symbolic expressions with SymbolicNeuralNetworks and compiled, so that only one differentiation is left for Zygote to do. This is the same route that hamiltonian_vector_field of HamiltonianNeuralNetworks.jl takes, and for the same reason.

Training on positions alone

LagrangianNeuralNetworks.LNNLoss needs $\ddot{q}$ in the data. When only positions are available, LagrangianNeuralNetworks.VariationalMidpointLoss trains the same architecture through the discrete Euler–Lagrange equations of the midpoint discrete Lagrangian

\[ L_d(q_n, q_{n+1}) = \Delta{}t\, L\!\left( \frac{q_n + q_{n+1}}{2}, \frac{q_{n+1} - q_n}{\Delta{}t} \right),\]

which ask that $D_2L_d(q_n, q_{n+1}) + D_1L_d(q_{n+1}, q_{n+2}) = 0$ along the data. Only the first derivative of the network is needed for this, because the chain rule through the midpoint is written out rather than taken with a nested Zygote.gradient.

LagrangianNeuralNetworks.LagrangianArchitecture — Type
LagrangianArchitecture <: Architecture

The supertype of an architecture whose network is a scalar Lagrangian $L(q, \dot{q})$ of an input that stacks $q$ on $\dot{q}$.

The losses of this package take any LagrangianArchitecture. A subtype needs two methods: AbstractNeuralNetworks.dim(arch), the input dimension $2n$, and Chain(arch), a chain with a scalar output. Without a dim method, AbstractNeuralNetworks logs an error and returns nothing, and the constructor of a loss fails there.

LagrangianNeuralNetworks.NormalisedLagrangian — Type
NormalisedLagrangian(arch::LagrangianArchitecture; base = zeros(2n), value = 0, momentum = zeros(n))

The Lagrangian of arch with its value and its momentum fixed at one base point (Offen 2025, Prop. 3.1), where $2n$ is dim(arch):

\[ \tilde{L}(x) = L(x) - L(x_b) - (\dot{q} - \dot{q}_b)^T\left(\nabla_{\dot{q}}L(x_b) - p_b\right) + c_b,\]

with $x = (q, \dot{q})$, $L$ the network of arch, $x_b$ = base, $\dot{q}_b$ its last $n$ entries, $c_b$ = value and $p_b$ = momentum. Then $\tilde{L}(x_b) = c_b$ and $\nabla_{\dot{q}}\tilde{L}(x_b) = p_b$ for every value of the parameters, which removes the constant and the linear gauge of a Lagrangian. With value and momentum both zero, the scale is not fixed, and is left to a condition of its own.

The network takes the same input as that of arch and has the same parameters, nested under the key L1. Every loss of the package takes a NormalisedLagrangian as it takes arch.

$\nabla_{\dot{q}}L(x_b)$ is computed in the forward pass, by a reverse pass over the layers of Chain(arch), so it is part of the expression that SymbolicNeuralNetworks traces and it depends on the parameters. That reverse pass supports Dense and Linear layers with the activations tanh, softplus and identity.

base and momentum are copied at construction. base, value and momentum are converted to the element type of the parameters. Where the network of arch is not finite at the base point, as where softplus overflows, the network of the wrapper is not finite anywhere.

A base or a momentum that is no AbstractVector throws a TypeError. A base of a length other than $2n$ or a momentum of a length other than $n$ throws a DimensionMismatch. An odd dim(arch), a layer of Chain(arch) that is no Dense, and an activation other than the three above throw an ArgumentError.

LagrangianNeuralNetworks.softplus — Function
softplus(x)

The activation $\log(1 + e^x)$, with the element type of x.

It is the default activation of LagrangianNeuralNetwork. With tanh, LNNLoss does not learn the harmonic oscillator: the solve against $\nabla_{\dot{q}}\nabla_{\dot{q}}L$ amplifies every sample where that block is near zero. With softplus it does; scripts/reproduction/k2_harmonic_oscillator.jl trains it on 16 seeds in each precision.

exp overflows, so softplus(x) is Inf above about 709 in Float64 and about 88 in Float32. There is no guard. The compiled input derivatives of a network are then NaN, and so is every loss built on them. For negative x, 1 + exp(x) rounds: the value loses relative accuracy, and it is 0 below about −37 in Float64 and about −17 in Float32.

LogExpFunctions also exports a softplus; a module that loads both packages qualifies the name.

LagrangianNeuralNetworks.LagrangianDerivatives — Type
LagrangianDerivatives(arch::Architecture; hessian = true)

Compile the gradient and the Hessian of the network of arch with respect to its input, once.

arch is any architecture whose Chain has a scalar output and that has a method of AbstractNeuralNetworks.dim, the input dimension $2n$; it need not be a LagrangianArchitecture. Evaluate the result with input_gradient and input_hessian. With hessian = false, only the gradient is built and compiled, and input_hessian throws an ArgumentError.

Implementation

The gradient and the Hessian are built as symbolic expressions with SymbolicNeuralNetworks.Jacobian, applied once and then again to its own result, and compiled with build_nn_function. They are not taken with Zygote inside a loss: differentiating a loss that itself contains a Zygote.gradient with respect to the network parameters fails with MethodError: no method matching getindex(::IdDict{Any, Any}). This is the route hamiltonian_vector_field of HamiltonianNeuralNetworks.jl takes, and for the same reason.

The compiled functions flatten a batch along the columns, $(1, 2n\cdot{}B)$ for the gradient and $(2n, 2n\cdot{}B)$ for the Hessian, so input_gradient and input_hessian reshape their output.

LagrangianNeuralNetworks.EulerLagrangeLoss — Type
EulerLagrangeLoss <: NetworkLoss

The Euler–Lagrange residual loss for a Lagrangian neural network (Offen 2025, App. B).

The loss asks the learned Lagrangian to satisfy the Euler–Lagrange equations on the data, with no solve for the acceleration:

\[ \mathtt{loss}(\mathcal{NN}, \mathtt{input}, \mathtt{output}) = \frac{1}{B}\sum_{b=1}^B \left\| \nabla_{\dot{q}}\nabla_{\dot{q}}L\,\ddot{q}_b + (\nabla_q\nabla_{\dot{q}}L)^T\dot{q}_b - \nabla_qL \right\|^2,\]

with the derivatives of $L$ taken at sample $b$ and $(\nabla_q\nabla_{\dot{q}}L)_{ij} = \partial^2L/\partial{}q_i\partial\dot{q}_j$. input stacks $q$ on $\dot{q}$ and has $2n$ rows, and output is $\ddot{q}$ and has $n$; trailing dimensions are samples too, so an input of size $(2n, s, B)$ goes with an output of size $(n, s, B)$, and the mean runs over all $sB$ samples. See _euler_lagrange_residual for the residual of one sample.

Unlike LNNLoss, the loss inverts no Hessian, so a velocity Hessian near zero does not amplify a sample. It is not normalised: the zero Lagrangian has the loss zero on any data.

A size mismatch of input and output throws a DimensionMismatch, and an empty batch an ArgumentError. NaN and Inf in the data propagate to the value.

where arch is a LagrangianArchitecture. An odd input dimension dim(arch) throws an ArgumentError, before anything is compiled.

LagrangianNeuralNetworks._euler_lagrange_residual — Function
_euler_lagrange_residual(H, g, q̇, q̈)

The Euler–Lagrange residual of one sample (Offen 2025, App. B),

\[ \nabla_{\dot{q}}\nabla_{\dot{q}}L\,\ddot{q} + (\nabla_q\nabla_{\dot{q}}L)^T\dot{q} - \nabla_qL,\]

where H is the $2n\times{}2n$ Hessian of the Lagrangian with respect to its input $(q, \dot{q})$, g the $2n$ gradient, and q̇ and q̈ the $n$ velocities and accelerations of the sample. The transpose contracts the first index of $(\nabla_q\nabla_{\dot{q}}L)_{ij} = \partial^2L/\partial{}q_i\partial\dot{q}_j$ with $\dot{q}$, as in _euler_lagrange_acceleration.

LagrangianNeuralNetworks.LNNLoss — Type
LNNLoss <: NetworkLoss

The loss for a Lagrangian neural network.

The network output is a scalar Lagrangian $L(q, \dot{q})$. The loss compares the acceleration its Euler–Lagrange equations predict against the acceleration in the data:

\[ \mathtt{loss}(\mathcal{NN}, \mathtt{input}, \mathtt{output}) = ||\ddot{q}(\mathtt{input}) - \mathtt{output}|| \,/\, ||\mathtt{output}||,\]

where $\mathtt{input}$ stacks $q$ on $\dot{q}$ and is therefore $2n$ rows tall, and $\mathtt{output}$ is $\ddot{q}$ and is $n$ rows tall. See lagrangian_acceleration for $\ddot{q}$.

Constructor

This can be called with a LagrangianArchitecture as its only argument:

LagrangianNeuralNetworks.lagrangian_acceleration — Function
lagrangian_acceleration(arch::LagrangianArchitecture)

Compute an executable expression of the acceleration that the Lagrangian arch predicts.

The Euler–Lagrange equations of a Lagrangian $L(q, \dot{q})$ are

\[ \frac{d}{dt}\frac{\partial{}L}{\partial\dot{q}} = \frac{\partial{}L}{\partial{}q},\]

which, expanded along a trajectory, reads

\[ \nabla_{\dot{q}}\nabla_{\dot{q}}L\,\ddot{q} + (\nabla_q\nabla_{\dot{q}}L)^T\dot{q} = \nabla_qL,\]

so the acceleration is

\[ \ddot{q} = (\nabla_{\dot{q}}\nabla_{\dot{q}}L)^{-1} \left( \nabla_qL - (\nabla_q\nabla_{\dot{q}}L)^T\dot{q} \right).\]

The transpose is not cosmetic. $\nabla_q\nabla_{\dot{q}}L$ is indexed $[i, j] = \partial^2L/\partial{}q_i\partial\dot{q}_j$, while the chain rule contracts the first index with $\dot{q}$. It disappears only for a Lagrangian whose position–velocity coupling happens to be symmetric.

Implementation

The gradient and the Hessian of the network with respect to its input come from LagrangianDerivatives, compiled once when lagrangian_acceleration is called. Trailing input dimensions beyond the first are flattened on the way in and restored on the way out, so an input of size $(2n, s, B)$, which is what Batch hands the loss, yields an acceleration of size $(n, s, B)$.

LagrangianNeuralNetworks.VariationalMidpointLoss — Type
VariationalMidpointLoss <: NetworkLoss

The loss that trains a Lagrangian neural network on positions alone, through the discrete Euler–Lagrange equations of the midpoint discrete Lagrangian.

It needs three consecutive positions and the timestep between them — no velocities and no accelerations.

The midpoint discrete Lagrangian is

\[ L_d(q_n, q_{n+1}) = \Delta{}t\, L\!\left( \frac{q_n + q_{n+1}}{2}, \frac{q_{n+1} - q_n}{\Delta{}t} \right),\]

and the discrete Euler–Lagrange equations ask that

\[ D_2L_d(q_n, q_{n+1}) + D_1L_d(q_{n+1}, q_{n+2}) = 0 .\]

The loss is the norm of that residual, relative to the norm of the two derivatives it is built from, so a Lagrangian scaled by a constant gives the same number.

Implementation

The two slot derivatives are written out with the chain rule rather than taken with a nested Zygote.gradient:

\[ D_1L_d = \frac{\Delta{}t}{2}\nabla_qL - \nabla_{\dot{q}}L, \qquad D_2L_d = \frac{\Delta{}t}{2}\nabla_qL + \nabla_{\dot{q}}L,\]

both evaluated at the midpoint. Only the first derivative of the network with respect to its input is then needed, and that comes from the compiled symbolic expression of LagrangianDerivatives, exactly as that of hamiltonian_vector_field of HamiltonianNeuralNetworks.jl does. Written the other way — a Zygote.gradient inside the loss — the parameter gradient fails with MethodError: no method matching getindex(::IdDict{Any, Any}).
